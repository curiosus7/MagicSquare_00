### 3.2 Q&A 로그

1. **Q:** 가장 최근에 4×4 부분 마방진을 다뤘을 때, 뭐 하려고 시작했고 계기는?  
   **A:** 수업에서 실습과제로 했다.

2. **Q:** 과제를 받고 첫 번째로 한 일은?  
   **A:** 빈칸 2개가 있었고, 마방진에 빠진 숫자를 찾아야 했다.

3. **Q:** 어렵다고 느낀 순간, 화면/종이에 실제로 뭐를 보고 있었는지?  
   **A:** 숫자 리스트를 보고 있었다.

4. **Q:** 숫자 리스트를 보기 직전에 뭘 하다가 펼쳐봤는지?  
   **A:** 숫자 2개를 넣었는데 검증에 20분 걸렸다.

5. **Q:** 20분 동안 검증한다고 반복한 일은?  
   **A:** 빈칸 2개 넣고 행·열·대각선 합을 맞췄는데, 대각선 하나를 빼먹어서 20분을 날렸다.

## 5. 표면 문제 vs 진짜 문제

### 5.1 표면 문제 (금지 — 솔루션 섞인 문장)

인터뷰 중 학습자가 직접 말한 솔루션형 문장은 없었다.  
과제 맥락에서 **표면 문제로 오기 쉬운** 문장:

| 표면 문제 (솔루션 섞임) | 왜 금지인가 |
|------------------------|------------|
| "`SquareValidator` 같은 검증기가 필요하다" | '검증기'가 해법 |
| "대각선까지 자동 체크하는 솔버가 있으면 좋겠다" | '솔버'가 해법 |
| "ECB 설계 도구가 있으면 실습이 쉬울 것이다" | '설계 도구'가 해법 |
| "실패 조건 체크리스트 앱이 필요하다" | '앱/체크리스트'가 해법 |

### 5.2 진짜 문제 (한 문장)

> **부분 마방진에 후보 숫자를 넣은 뒤, 손으로 행·열·대각선 합을 검증할 때 검사 항목을 하나 빼먹어 잘못된 답을 맞다고 오래 붙잡으며 20분을 낭비한다.**

## 7. 세션 3 워크북 (Mom Test → R-G-I-O)

### 7.1 주제 (1문장)

> **4×4 부분 마방진에서 빈칸을 채운 직후, 행·열·대각선 10선이 각각 34인지 빠르게 확정하고, 틀리면 어느 줄인지 바로 짚을 수 있게 검증 규칙과 테스트 루프를 만든다.** 미완성 격자(0 포함)는 `incomplete`로 구분한다.

*(솔루션 최소화 — 앱·솔버·ECB 도구가 아니라 **판정·확인 비용**만 다룸)*

### 7.2 R-G-I-O

| | 내용 |
|---|---|
| **R — Role** | 4×4 **부분** 마방진 학습자. 빈칸 2개(0)를 1~16으로 채운 뒤 **맞았는지 스스로 확인**해야 함 *(수업 실습 + ECB·실패 조건 과제 병행)* |
| **G — Goal** | 빈칸 채운 후 **10선 합 34 여부를 즉시 판정**하고, 틀리면 **어느 행·열·대각선**인지 식별 *(20분 낭비 → 처음·한 번에)* |
| **I — Input** | `grid: list[list[int]]` — 4×4 정수 격자. 셀 값 **0**(빈칸) 또는 **1~16** |
| **O — Output** | `validate_lines(grid)` → **ValidationResult**: `ok` (bool), `status` (`"pass"` \| `"fail"` \| `"incomplete"`), `lines[]` — fail 시 **틀린 줄만** `{ id, sum, expected: 34 }`. 줄 ID: `row:0`~`row:3`, `col:0`~`col:3`, `diag:main`, `diag:anti`. **R5:** 격자에 `0`이 하나라도 있으면 `status=incomplete`, 합 계산·34 비교는 수행하지 않음 |

### 7.3 성공 기준 3개 (Mom Test 증거 연결)

| # | 성공 기준 | 연결 증거 |
|---|-----------|-----------|
| 1 | **`validate_lines(grid)`** 한 번으로 **10선×34 검증**을 수행한다 (행 4 + 열 4 + 대각 2) | “행·열·**대각선** 합 맞췄는데 **대각선 하나를 빼먹어서**” |
| 2 | Test Loop **Red→Green**: Red — 합≠34 → `ok=false`, `status=fail`; Red — `0` 포함 → `status=incomplete` (T3); Green — 정답 격자 → `ok=true`, `status=pass` (T1) | “**20분 날렸다**” → 같은 실패를 테스트로 **1번에 재현** |
| 3 | fail 시 `lines[]`에 **틀린 줄 ID**(`row:2`, `diag:main` 등)와 `sum`, `expected: 34`를 반환한다 (10선 전부 검사, 줄 누락 없음) | “맞는지 **판정하지 못하고**” 같은 시도 반복 → **줄 단위**로 짚어야 함 |

### 7.4 표면 문제 — 이번 프로젝트에서 하지 않을 것

| 하지 않음 | 이유 (Mom Test) |
|-----------|-----------------|
| `SquareValidator` 같은 **검증기 프레임워크** 전체 | ‘검증기’가 해법 — 이번 고통은 **10선 판정 규칙** 고정 |
| **대각선 자동 체크 솔버** / 빈칸 자동 채우기 / 힌트 | ‘솔버’가 해법 — 학습자 고통은 **풀기**보다 **맞는지 확인** |
| **ECB 설계 도구** / BCE 전체 / `GridUI` / `InputHandler` | ‘설계 도구·UI’가 해법 — ECB·실패 조건은 **병행 과제**, 세션 3 범위 밖 |
| **실패 조건 체크리스트 앱** | ‘앱/체크리스트’가 해법 — **판정·재현**이 먼저 |
| 1~16 중복·범위 검증까지 한꺼번에 | 세션 3 범위 밖 — **합 34 판정**에 집중 |

### 7.5 8계층 — 이번 세션에서 만들 것만

| 계층 | 세션 3에서 할 일 | Mom Test 연결 |
|------|------------------|---------------|
| **Rule** | R1~R5: **행·열·대각선 합 = 34** 판정. R5 — 0(빈칸) 포함 시 `status=incomplete` (**fail과 구분**, 합 검증 생략) | “34가 안 맞았는지” **판정 기준**을 코드·문서로 고정 |
| **Command** | `validate_lines(grid)` → `ValidationResult` — 10선 합 계산 + 34 비교 + fail 시 **틀린 줄 ID·sum·expected** 반환 | 합 확인에 **20분** → **한 Command**로 대체 |
| **(Skill)** | *(선택)* pytest 실행 / 4×4 격자 fixture 준비 Skill | 매번 손으로 10선 더하기 제거 |
| **Test Loop** | Red: 합≠34 → `ok=false`, `status=fail`, **실패 줄** assert; Red: `0` 포함 → `status=incomplete` (T3); Green: 정답 격자 → `ok=true`, `status=pass` (T1) | **20분 낭비** → **같은 실패를 1번에 재현** |

**이번 세션에서 만들지 않음:** Entity(`MagicSquare`/`Cell`), Boundary(`ResultDisplay`), Solver, MissingFinder, ECB 분류표·실패 조건 작성 도구, 전체 BCE

## 8. Mom Test 해석 (멘토 노트)

### 검증된 것

- 문제의 핵심은 "마방진이 어렵다"가 아니라 **검증 단계에서의 누락·시간 손실**이다.
- 숫자 채우기 자체보다 **"맞다고 확신하는 과정"**이 병목이다.
- **20분**이라는 측정 가능한 비용이 있어, 문제가 실제 행동에서 도출되었다.

### 아직 검증되지 않은 것

- 일회성인지, 다른 크기/빈칸 수에서도 반복되는지
- 코드로 풀 때도 동일한 검증 누락이 발생하는지
- ECB·실패 조건 작성이 별도의 고통인지

### 다음 인터뷰 질문 후보 (솔루션 없이)

- "그 실습 말고, 비슷하게 검증하다 시간 날린 적 또 있어?"
- "20분 끝에 제출은 했어, 아니면 포기했어?"
- "대각선 빼먹은 걸 알게 된 순간, 그때 뭐랑 비교했어?"
