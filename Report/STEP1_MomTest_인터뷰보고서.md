## 1. 개요

4×4 부분 마방진을 다루는 학습자 1명을 대상으로 Mom Test 인터뷰를 진행했다.  
솔루션·기능 제안 없이, 수업 실습 과정에서 실제로 겪은 행동과 비용을 추출했다.

---

## 2. 페르소나

**4×4 부분 마방진을 손으로/코드로 다루는 학습자**

- 수업 실습과제로 4×4 부분 마방진(빈칸 2개) 문제를 수행
- ECB(Entity–Control–Boundary) 설계 분류 및 실패 조건 도출 과제 병행
- 손 계산·검증 중심으로 과제 수행

---

## 3. 인터뷰 답변 (과거 사실)

| 항목 | 내용 |
|------|------|
| **언제** | 수업 실습과제로 **한 번** 수행 |
| **과제** | 4×4 격자, 합=34, 빈칸 2곳에 1~16 중 빠진 숫자 채우기 |
| **병행 작업** | ECB 분류(Entity/Control/Boundary) + 실패 조건 3가지 이상 도출 |
| **막힌 순간** | 숫자 2개를 넣은 뒤 **검증에 20분** 소요 |
| **그때 한 일** | 행·열·대각선 합을 맞췄다고 확인했으나 **대각선 하나를 빼먹음** |
| **결과** | 잘못된 검증을 전제로 **20분을 소모** |
| **막혔을 때 보던 것** | 숫자 리스트 |

### 인터뷰 로그 (요약)

1. **Q:** 가장 최근에 4×4 부분 마방진을 다뤘을 때, 뭐 하려고 시작했고 계기는?  
   **A:** 수업에서 실습과제로 했다.

2. **Q:** 과제를 받고 첫 번째로 한 일은?  
   **A:** 빈칸 2개가 있었고, 마방진에 빠진 숫자를 찾아야 했다.

3. **Q:** 어렵다고 느낀 순간, 화면/종이에 실제로 뭐를 보고 있었는지?  
   **A:** 숫자 리스트를 보고 있었다.

4. **Q:** 숫자 리스트를 보기 직전에 뭘 하다가 펼쳐봤는지?  
   **A:** 숫자 2개를 넣었는데 검증에 20분 걸렸다.

5. **Q:** 20분 동안 검증한다고 반복한 일은?  
   **A:** 빈칸 2개 넣고 행·열·대각선 합을 맞췄는데, 대각선 하나를 빼먹어서 20분을 날렸다.

### 미확인 항목

- 대각선 누락을 **어떻게** 깨달았는지
- 최종 제출 여부
- ECB·실패 조건 작성에 든 시간

## 4. 표면 문제 (금지 — 솔루션 섞인 문장)

인터뷰 중 학습자가 직접 말한 솔루션형 문장은 없었다.  
다만 과제 맥락에서 **표면 문제로 오기 쉬운** 문장들:

| 표면 문제 (솔루션 섞임) | 왜 금지인가 |
|------------------------|------------|
| "`SquareValidator` 같은 검증기가 필요하다" | '검증기'가 해법 |
| "대각선까지 자동 체크하는 솔버가 있으면 좋겠다" | '솔버'가 해법 |
| "ECB 설계 도구가 있으면 실습이 쉬울 것이다" | '설계 도구'가 해법 |
| "실패 조건 체크리스트 앱이 필요하다" | '앱/체크리스트'가 해법 |

→ 위 문장들은 **해법이 이미 포함**되어 있으므로 진짜 문제로 사용하지 않는다.

## 5. 진짜 문제 (한 문장)

> **부분 마방진에 후보 숫자를 넣은 뒤, 손으로 행·열·대각선 합을 검증할 때 검사 항목을 하나 빼먹어 잘못된 답을 맞다고 오래 붙잡으며 20분을 낭비한다.**

---

## 6. Mom Test 해석 (멘토 노트)

### 검증된 것

- 문제의 핵심은 "마방진이 어렵다"가 아니라 **검증 단계에서의 누락·시간 손실**이다.
- 숫자 채우기 자체보다 **"맞다고 확신하는 과정"**이 병목이다.
- **20분**이라는 측정 가능한 비용이 있어, 문제가 실제 행동에서 도출되었다.

### 아직 검증되지 않은 것

- 일회성인지, 다른 크기/빈칸 수에서도 반복되는지
- 코드로 풀 때도 동일한 검증 누락이 발생하는지
- ECB·실패 조건 작성이 별도의 고통인지

### 다음 인터뷰 질문 후보 (솔루션 없이)

- "그 실습 말고, 비슷하게 검증하다 시간 날린 적 또 있어?"
- "20분 끝에 제출은 했어, 아니면 포기했어?"
- "대각선 빼먹은 걸 알게 된 순간, 그때 뭐랑 비교했어?"
